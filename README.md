# ToolDock (試作)

別々に起動した exe の窓を、1 つの枠にタブでまとめる Windows 用の試作です。
自作ツールを起動するたびにタスクバーと窓が増えて散らかる、を減らすためのもの。

```sh
uv run tooldock.py              # tooldock.toml のツールを並べたドックを開く
uv run tooldock.py --rescue     # ドックが落ちて隠れたままの窓を元に戻す
```

- 右上の「+ 起動 / 取り込む」から、`tooldock.toml` のツールを起動するか、起動中の窓を取り込む。
  起動中のツールがあれば 2 つ目は起動せず、その窓を取り込む
- タブの右クリック: 「ドックから外す (窓は残す)」「ツールを閉じる」。中クリックでも閉じる
- ドックを閉じると、取り込んだ窓は元の枠・位置に戻る (ツールは終わらない)

## 仕組み (仮想タブ)

相手の窓の中に手を入れず、トップレベルの窓のまま扱う。

- 取り込むと、タイトルバーと縁を外してドックの本体の上に重ね、`WS_EX_TOOLWINDOW` でタスクバーのボタンを消す
- 選んでいないタブの窓は隠す。ドックの移動・大きさ変更・最小化に合わせて、選んでいる窓を動かす
- 重なり順: ドックが前面になったらツールを `SetForegroundWindow` で前面にし、ツールが前面になったらドックをその直下へ付ける。
  別プロセスの窓は `HWND_TOP` で上げようとしても前面の窓より上に上がらないことがあり、ドックのタイトルバーで戻ると
  ツールが他のアプリの後ろに残った。ツールが後ろにあるうちにドックを下げると、ドックまで後ろに回る。
  前面にいないプロセスからの `SetForegroundWindow` は拒否されるので、前面化は人の操作 (クリック) を起点にする
- 窓の所有者 (owner) は変えない。変えると、ドックが終わるときに相手の窓まで壊れるおそれがある
- 取り込んだ窓の元の状態は `%LOCALAPPDATA%\ToolDock\state.json` に控える。ドックが落ちても、次の起動か `--rescue` で戻す
- 前景の窓の変化 (WinEvent) は別スレッドで受ける。tkinter の mainloop と同じスレッドで ctypes のコールバックを受けると、
  Python ごと落ちた (`PyEval_RestoreThread: the GIL is released`)

## 確かめ方

```sh
uv run tooldock.py --selftest LPortMan PortWho   # 取り込み・切り替え・追従・最小化・別アプリとの重なり・外す・閉じる (25 項目)。docs/ に画像
uv run check_rescue.py LPortMan                  # 取り込んだまま落として、--rescue で戻るか
```

- 位置と表示状態だけ見ると、窓がドックの後ろに回っていても通ってしまう。`WindowFromPoint` が
  その窓を返すか (手前に見えているか) まで見ること
- タブの切り替えと、別のアプリから戻る操作は、本物のマウスでクリックする (試験中はカーソルが動く)。
  プログラムから前面化すると、Windows の扱いが人の操作と違い、実際には起きない失敗や、実際に起きる失敗の見逃しになる
